# Privacy policy

SuperMatt is a set of agent skills: Markdown instructions and a few shell and JavaScript scripts that run inside Claude Code, Codex, Cursor, OMP, or another compatible agent. It has no hosted service, account, or telemetry. Optional remote native evaluation runs an SSH endpoint on a maintainer machine you configure; it is not a SuperMatt-operated service. The project maintainer receives no data automatically.

## Where your data goes

Your agent handles your conversation and code under the terms of its own provider. Beyond that, some skills pass data to tools and services you set up yourself. `docs/agents/cross-model.json` controls external peer processes used by `code-review` and `jury`. Its `host-only` mode starts no supported external peer subprocess and keeps the work on current-host readers; those readers still use the host's configured model provider.

- **`code-review`** may send every review axis and finding validation to the configured Claude, Codex, Cursor Agent, or OMP CLI. The peer receives the diff, checked spec, repository standards, findings, review instructions, and referenced text evidence. `auto` selects only the hardened Claude or Codex adapters. Cursor is explicit-only because Ask mode inherits user and repository rules, MCP, plugins, executable hooks, and stored sessions. OMP is explicit-only, receives an evidence bundle with repository tools disabled, and has weaker inherited-configuration and MCP isolation. It cannot inspect omitted evidence.
- **`jury`** may give one vote and review seat to the same configured adapter. That adapter receives the question, options, criteria, facts, constraints, and required text evidence. Cursor and OMP require interactive confirmation immediately before launch because a repository file is untrusted input and cannot consent to their inherited configuration, MCP, hook, or session limits.
- **`to-spec`, `to-tickets`, `triage`, `wayfinder`, `implement`, `code-review`, and `orchestrate`** read or write issues on the issue tracker you choose in `setup-supermatt-skills`: GitHub through the `gh` CLI, GitLab through the `glab` CLI, or local Markdown files.
- **`ship-pr`** pushes the branch, opens a pull request, and merges it on GitHub through the `gh` CLI.
- **Merge Train handoff in Tern** reads open labelled PRs and comments through `gh`, records the responsible local session and coordinator, and sends a fixed conflict message through their configured Tern inbox or registered worker prompt. If neither can receive it, it shows an operator notification. It does not forward comment prose, merge, rebase, or push by itself.
- **`babysit-pr`** pushes the branch, opens a pull request, reads its review threads, comments and checks, replies to and resolves review threads, and updates the branch on GitHub through the `gh` CLI. It never merges. **`recover-ci`** reads CI logs, reruns failed jobs through `gh`, and can commit and push verified repair code to the caller's selected branch. It never merges.
- **`orchestrate`** drives Claude Code, Codex, Cursor, or OMP worker sessions through `herdr`, creates git worktrees through `tern-wt` in tern-worktrees' worktree root when `tern-wt` is installed and under the repo's `.claude/worktrees/` otherwise, reads Herdr-reported session references, closes and comments on issues through the configured tracker, and shows a Tern notification on its own pane when it stops. Cursor workers inherit the active session's authoritative model ID when available, otherwise their harness default. OMP workers take their model and effort from orchestrate's phase by tier table.
- **OMP finish cleanup in `ship-pr` and `orchestrate`**, when the local `worktree_finish` extension is available, passes finished and explicitly retained worktree paths to that extension. It inspects local worktree/session state and PR heads, merge state, and post-merge workflows through your configured GitHub access, then requests explicit consent through the real OMP `ask`. Standalone shipping offers its selected shipping worktree even when the session runs in main; orchestration offers the run's successfully finished worktrees only once at the end. You can include other eligible MERGED-PR worktrees of the same repository, or keep everything. Main, parked or interrupted lanes, modified, locked, active, and uninspectable worktrees remain. Only the displayed approved scope can be removed; local branches follow tern-worktrees' teardown setting, with no remote-branch, general process, or container cleanup. The extension ends a session only if its current cwd worktree is selected, waits for actual process exit through an external executor before removing that worktree and closing its tab, keeps OMP history, and sends the result as a Tern notification. A session in main, including the orchestration coordinator, stays open. Other hosts and unavailable-extension paths retain the existing dry-run and user-approval behavior.
- **`retro`** reads local Claude Code, Codex, Cursor, or OMP session transcripts selected from verified host and workspace roots. Transcripts can contain prompts, code, tool output, credentials, and inlined skill bodies. The parser keeps this evidence local unless you explicitly publish it.
- **`qa`** may exercise live services, accounts, or paid commands explicitly authorized by the repository's optional `docs/agents/qa.md`, within its budget, stop rules, and forbidden-effect limits. Named role-play agents receive QA-written briefs and produce raw interactions for independent QA judgment. Those services and the agents' configured providers receive the scenario inputs; retained evidence can contain their responses and account data. An absent or empty convention grants no such authorization, and the networkless fallback remains networkless.
- **`research`** reads public web pages and documentation to answer your question.
- **Native skill evaluation** uses the installed Codex CLI and its existing authentication for paid model calls. When `SUPERMATT_NATIVE_EVAL_SSH` is configured, `scripts/native-eval-remote.sh` sends the committed candidate and the history needed beyond the worker's remote-tracking default branch to that SSH destination as a Git bundle. That machine fetches the public trusted origin, evaluates with its own Codex login, and returns reports, redacted traces and observations to the worker. No login credentials are copied from either machine. Coverage records include the remote hostname and commit identities. Candidate catalogue code runs under Node permissions with an empty environment, but this is not a hostile-code sandbox and Node 22/24 do not block its network access. Use only trusted candidates and an endpoint the operator has approved.

Each of those services handles the data under its own privacy policy.

## What SuperMatt writes locally

Skills write files into your working directory when you use them: specs, tickets in a local tracker, `GLOSSARY.md`, ADRs, handoff documents, research notes, reports, and prototypes. They stay on your machine unless you commit and push them. QA and review can also create temporary copies and evidence in OS temporary directories. `implement-spec` creates a git worktree for each ticket and runs the repository's documented setup commands in each worktree it creates, so a dependency install there downloads packages from the registries your project uses. It keeps its run state and evidence (task graph, worker contracts, commit SHAs, QA and worker evidence) under `${XDG_STATE_HOME:-$HOME/.local/state}/implement-spec/<repo-key>/<spec-key>/`, keyed by SHA-256 digests of repository and full spec identities recorded with the run, outside the repository, and leaves that directory in place after the run for you to delete. When the repository's CI configuration shows that a push of the branch starts no CI run, it pushes its worker and integration branches to your remote as it goes, so a host crash loses no commits. It deletes the worktrees it created once their work is in the integration branch. For a worktree holding a submodule, that deletion also removes the submodule repositories Git keeps for it, so it runs only when every commit they hold is on a remote or in the main worktree's copy. `babysit-pr` keeps its state for each pull request under the repository's common Git directory, normally `.git/supermatt/babysit-pr/`, shared across linked worktrees. Git never commits or pushes that state.

The Merge Train watcher keeps PR registrations (repository, number, local pane, process and session identity, and optional registered agent name) and per-head delivery receipts in the caller-selected state directory outside the worktree. These records survive a stopped shipping turn; remove them when retiring the watch. The watcher checks GitHub outside model turns. Its background event wait returns on new work so the launching host can resume, and a trusted session message can start a turn in the registered recipient. The process itself is not installed as a service or restarted after reboot.

With OMP finish cleanup enabled, `orchestrate` retains delivered issue worktrees and their local branches through its report-only retrospective and the final consent choice. Its private state is `${XDG_STATE_HOME:-$HOME/.local/state}/supermatt/orchestrate/<repo-key>/<run-key>/finish.json`, outside lane worktrees, with directory mode `0700` and file mode `0600`. The repository key hashes the canonical main-checkout path. The run key combines a UTC timestamp and UUID and is reported to the operator. State records coordinator identity, lane paths and status, finished and retained paths, evidence paths, owned job handles/process identities, termination evidence, registered scope, observed refusals and cleanup results. It restores that same file before continuation, restart or replacement sessions and keeps prior retained exclusions. Unknown paths remain excluded. Missing or unreconciled state blocks cleanup rather than inventing an empty run. Parked paths are explicitly excluded from both choices, including clean worktrees with MERGED PRs whose worker has exited. Before any final offer, the coordinator stops and awaits its own control jobs while preserving their logs and records. Parked workers and unrelated processes stay untouched. An unchanged observed declined scope is not offered again after a restart. Spec-verification and non-READY triage worktrees keep their temporary-worktree removal path, and recorded session history stays.

A failed call to an available finish tool, failed state persistence/restoration, or unproven coordinator-job exit blocks cleanup. The legacy dry-run path applies to absent capability or documented host/worktree fallbacks, not these failures.

The remote native-evaluation endpoint retains its bare trusted-origin cache under `${XDG_CACHE_HOME:-$HOME/.cache}/supermatt-native-eval/`. It removes per-run candidate data, reports and execution state on exit after streaming the report archive. The worker retains the extracted report in the client-selected `--out` directory. Neither endpoint automatically publishes that evidence.
