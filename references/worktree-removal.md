# Worktree removal with submodules

Follow this after the calling skill has confirmed its own removal conditions (the worktree was created by this run, its agents have exited, its tree is clean) and a plain `git worktree remove <worktree>`, without `--force`, was refused. The calling skill decides what happens to a worktree this rule retains.

Git refuses that removal for any worktree holding a submodule repository, even a clean or deinitialized one (`working trees containing submodules cannot be moved or removed`), and `--force` deletes those repositories with the worktree. Any other refusal is not covered here: retain the worktree. After that refusal, run `git -C <worktree> submodule absorbgitdirs`, which moves each submodule repository embedded in the worktree, nested ones included, into its modules directory. It leaves a repository that a `.git` file points to elsewhere, and one a deinitialized or removed submodule left behind, so confirm that no Git repository remains inside the worktree directory, whatever its name: for each path `find <worktree> -name HEAD` prints, a file or a symbolic link alike, `git --git-dir=<its directory> rev-parse --git-dir` fails. Then rerun the removal with `--force` only when the worktree also passes these checks:

- `git submodule status --recursive` shows no `+` or `U` prefix, so each initialized submodule sits at the commit the worktree's `HEAD` records. A deinitialized submodule (`-`) goes on to the next check, because its repository stays behind.
- No commit exists only in this worktree's submodule repositories. For each repository under the worktree's modules directory (`git -C <worktree> rev-parse --git-path modules`), nested, deinitialized, and removed ones included, list the commits that no remote-tracking ref contains: `git --git-dir=<repository> --work-tree=<repository> rev-list <pinned commit> --all --reflog --not --remotes`. The listing keeps commits that only a local tag or a reflog holds, since both go with the worktree. Pass the pinned commit `git submodule status --recursive` shows for that submodule, and none for a repository it no longer lists, such as one the worktree's branch removed with `git rm`; `--work-tree` keeps Git from entering a submodule directory that no longer exists. Each listed commit must also be held by the repository at the same relative path under the main worktree's modules directory (`git -C <main worktree> rev-parse --git-path modules`, the main worktree being the first entry of `git worktree list`): `git --git-dir=<that repository> --work-tree=<that repository> rev-list --all --reflog` lists it.

Retain the worktree when any check fails, including when a check's command itself fails, and report the check it failed and any commit that exists only there.
