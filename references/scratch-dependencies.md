# Scratch dependency preflight

Before a copied tree is edited or runs a reproduction, mutation, or hook, check its containment and prove its dependencies resolve from that tree. A worktree can inherit packages from an ancestor even when its own `node_modules` exists; copying that local directory alone loses the inherited packages.

Run `node <this file's directory>/check-scratch-containment.mjs <scratch>` with both paths shell-quoted, or use Bun with `--no-env-file`. It rejects a linked scratch root, unresolved symlinks, and links whose canonical targets escape the scratch tree, except a link to a system file the user cannot change: a non-directory owned by root, not writable by the current user, and outside the user's home. Directories never qualify, since a read-only directory can hold writable paths.

That exception covers a Python virtualenv, whose `bin/python` links to a system interpreter such as `/usr/bin/python3.12`. Leave that link as it is and never copy the interpreter into scratch. The check accepts the link instead of having scratch copies exclude `.venv` and similar environment directories, because a Python check usually needs the environment's installed packages, and a write through the link fails rather than changing the interpreter. An interpreter the user owns or one under the home directory (pyenv, uv, or a per-user Homebrew) still fails the check: recreate the environment inside scratch with the repository's supported setup and a copied interpreter, such as `python3 -m venv --copies`.

Copy other required external targets into scratch and replace those links there, then rerun the check after dependency setup and before editing or execution. Do not modify the external targets. This is a preflight for a quiescent tree, not a sandbox against concurrent filesystem changes.

For Node or Bun, run `node <this file's directory>/check-scratch-dependencies.mjs <scratch> <required-package>...`, using the imports required by the check and its preload. Bun can run the same helper with `bun --no-env-file`. The helper treats Node built-ins as resolved and lists each by name, including when the check requires only built-ins. Package entry points still resolve without execution and are reported with their canonical paths. A missing package still reports a setup failure and exits 1. Run it against the source tree to locate a missing package's actual installation, then prepare the scratch dependencies with the repository's supported setup. Keep generated caches private and preserve restrictions on environment files and credentials.

After resolution passes, run the actual runtime's preload or smallest startup check from the scratch tree. Other ecosystems use their equivalent dependency-resolution and startup checks. A failed preflight stops the scratch run before a mutation or push; report it as a setup failure. Keep normal hooks enabled. Retain the dependency paths and successful preflight commands with the verification evidence for the next worker.
