# Scratch dependency preflight

Create each disposable repository copy with `node "<this file's directory>/copy-scratch-tree.mjs" "<repo>" "<scratch>"` (Bun: `bun --no-env-file`), using absolute, shell-quoted paths. The destination must not exist, its parent must exist, and it must be outside the repository. The helper first tries a copy-on-write clone of the directory (`clonefile` through Python 3's standard-library `ctypes` on macOS, `cp --reflink=always` elsewhere), removes every `.git` entry and special or device file without following symlinks, and preserves file modes. A failed or unavailable clone or cleanup discards the partial copy before the original rsync fallback; the command reports its method. Copies include ignored and untracked files, and writing an ordinary file in the copy leaves the repository unchanged. The following preflight still runs for either method.

Before a copied tree is edited or runs a reproduction, mutation, or hook, check its containment and prove its dependencies resolve from that tree. A worktree can inherit packages from an ancestor even when its own `node_modules` exists; copying that local directory alone loses the inherited packages.

Run `node <this file's directory>/check-scratch-containment.mjs <scratch>` with both paths shell-quoted, or use Bun with `--no-env-file`. It rejects a linked scratch root, unresolved symlinks, and links whose canonical targets escape the scratch tree, except a link to a system file the user cannot change: a non-directory owned by root, not writable by the current user, and outside the user's home. Directories never qualify, since a read-only directory can hold writable paths. A link whose target does not exist fails as `dangling link (target missing in scratch): <link> -> <target>`. It also rejects a `.git` entry at any depth that is not a directory, such as the `gitdir:` pointer file a raw copy of a linked worktree keeps, since Git commands in scratch would follow it into the real repository and commit on its branch; a `.git` directory, such as `git init` creates in the copy, passes. In each directory holding `pyvenv.cfg`, it fails a `bin/` script whose interpreter path is absolute and outside scratch (`shebang points outside scratch`), read from the `#!` line or from line 2 of the `/bin/sh` `'''exec'` launcher, unless that path is a root-owned entry ending at such a system file, as `/usr/bin/env` and `/usr/bin/python3` are. It also fails a line of a top-level `.pth` file in `site-packages` that resolves outside scratch (`.pth path points outside scratch`), since Python would import from there.

That exception covers a Python virtualenv, whose `bin/python` links to a system interpreter such as `/usr/bin/python3.12`. Leave that link as it is and never copy that interpreter into scratch. The check accepts the link instead of having scratch copies exclude `.venv` and similar environment directories, because a Python check usually needs the environment's installed packages, and a write through the link fails rather than changing the interpreter.

Whenever the copy holds a Python virtualenv (a directory holding `pyvenv.cfg`), run `node "<this file's directory>/prepare-scratch-python.mjs" "<repo>" "<scratch>"` (Bun: `bun --no-env-file`) right after the copy and before the containment check, with the same two paths in the same order as the copy helper. It refuses a scratch root that is a symlink, missing, or the repository or inside it, writes only inside scratch, and never writes through a link. For each virtualenv whose interpreter the user owns (pyenv, uv, or a per-user Homebrew), it copies that runtime, the parent of the `bin` directory holding the interpreter's canonical path, to `<venv>/.scratch-python/<runtime>`, relinks the `bin/` links that left scratch into it, and points `pyvenv.cfg`'s `home`, `executable`, and `command` at the copy; a link to a locked system interpreter stays. In every virtualenv, it replaces the repository path, as given and canonical, with the scratch path in each text file outside the copied runtime: editable-install `.pth` lines and finder modules, `direct_url.json`, `activate` scripts, and console-script interpreters. A rewritten `#!` line longer than 127 bytes or holding a space becomes the `/bin/sh` `'''exec'` launcher that pip and uv write. It then runs each virtualenv's `bin/python` from `/` and fails unless `sys.prefix` is that virtualenv. It prints each change, then a summary; a rerun on the same scratch changes nothing, and a failure prints one `Scratch Python preparation failed: <reason>` line and exits 1. A virtualenv created with `--copies` keeps its interpreter, and conda environments, which have no `pyvenv.cfg`, and Windows layouts are not handled. Two cases are unverified: a uv runtime relocated on macOS, and a pyenv build with `--enable-shared`, which may still load `libpython` from its original prefix where the containment check cannot see it.

Copy other required external targets into scratch and replace those links there, then rerun the check after dependency setup and before editing or execution. Do not modify the external targets. This is a preflight for a quiescent tree, not a sandbox against concurrent filesystem changes.

For Node or Bun, run `node <this file's directory>/check-scratch-dependencies.mjs <package-directory> <required-package>...`, using the imports required by the check and its preload. `<package-directory>` is the package that runs the check inside the scratch tree: the one whose `package.json` declares the test runner and the check's imports. In a workspace that is usually a member directory such as `<scratch>/apps/x`, not the scratch root, since a workspace root often declares neither. Bun can run the same helper with `bun --no-env-file`. The helper treats Node built-ins as resolved and lists each by name, including when the check requires only built-ins. Package entry points still resolve without execution and are reported with their canonical paths. A missing package still reports a setup failure and exits 1. When workspace members under the given directory declare the missing package in `dependencies` or `devDependencies`, the failure also names each one, in the form ``vitest is declared by `apps/x`: rerun with `<scratch>/apps/x` ``; rerun from the member that runs the check. Run it against the same package directory in the source tree to locate a missing package's actual installation, then prepare the scratch dependencies with the repository's supported setup. Keep generated caches private and preserve restrictions on environment files and credentials.

After resolution passes, run the actual runtime's preload or smallest startup check from the scratch tree. Other ecosystems use their equivalent dependency-resolution and startup checks. A failed preflight stops the scratch run before a mutation or push; report it as a setup failure. Keep normal hooks enabled. Retain the dependency paths and successful preflight commands with the verification evidence for the next worker.
